HoldLine

FastAPI · Anthropic API · SQLite · pytest · 13,138 lines · 520 tests

A voice agent that places real, time-limited holds on bakery inventory over the phone. The problem it exists to solve is that an assistant which sounds confident about stock it has not checked is worse than no assistant, because someone drives across town for a cake that was never there.

The design decision: every response is validated after generation against the tool results from that same turn, and violations are tiered by consequence. A wrong quantity gets one retry. An allergen claim is never retried and never softened, it hard-blocks to a human. The two are not comparable mistakes, so they do not get the same handling.

Testing it against the live model found four defects that 444 passing offline tests had not, and three of those were structurally invisible offline. "And no allergies" escalated as an allergy. "Twenty minutes" was read as containing a nut allergy. That is the argument for a live pass at the end of every phase rather than trusting a green suite.

Still being built. Four of nine phases are done; the phone layer and the LangGraph port are not. The repository is private, so nothing here is open for you to check. I verified these figures against the working tree rather than copying them off a résumé, but you cannot, and I would rather say that than imply otherwise.

Silent Failure Detection

Python · scikit-learn · SciPy · import-linter · pytest · 8,209 lines · 261 tests

A credit-default model, frozen after training on 2013 H1, deployed across 35 monthly windows of Lending Club originations covering 1,054,948 loans, monitored with unsupervised signals only, then graded against labels that took two years to arrive.

The finding: AUC held flat (0.6719 → 0.6661) while Brier rose 17% and the calibration gap widened 27-fold. A team defining degradation as an AUC drop would have concluded nothing happened. Meanwhile the model was under-stating portfolio default risk by about 36% at its worst, and pricing consumes the probability, not the rank.

The headline number the project was built to produce was early-warning lead time. The answer was zero. Three of six detectors fired on the first window and every window after; one never fired at all. A detector that alerts on 100% of windows has maximum nominal lead time and no information, so I wrote pre_onset_alert_rate specifically to make that unquotable as a success.

It also retracts its own headline. An earlier write-up reported the estimators as anti-correlated with truth (r = −0.38, p = 0.023). Both series are autocorrelated; after correction the effective sample size falls from 35 to 13 and p becomes 0.195. The claim did not survive, so the repository says so, in the commit that removed it.

ClinIQ

Claude · pgvector · LangGraph · FHIR R4 · UMAP · HDBSCAN · Docker

Substance-use risk detection over 52,184 public patient-written drug reviews, built for the NSF NRT Research-A-Thon. Three retrieval tiers were run against the same labelled set: rules, embedding cosine similarity, and Claude over pgvector.

The finding: no tier won. Rules scored 0.86 precision / 0.85 recall in 0.05 s. Embeddings reached perfect recall at 0.50 precision, with 295 false positives. Claude+RAG reached 0.94 precision but 0.40 recall, and took 29 minutes. The cheapest tier was the most balanced, and the expensive one bought precision by missing more than half the cases.

Flagged reviews were clustered into 37 behavioural cohorts with UMAP and HDBSCAN over 384-dimensional embeddings, with the share of low-rated reviews tracked across the 2008–2017 opioid-crisis decade. Every embedding stores its source_url, so any answer can be traced to the CMS or ICD-10 document it came from.

Since extended: FHIR R4 ingestion (118,868 synthetic-patient resources in 3.8 s, zero PHI leaks, hash-chained audit log); a LangGraph prior-authorization agent where the engine decides and only a clinician can deny (89/89 missing-evidence cases paused); and an active-learning labelling workbench that matched 95% of full-data precision with 1,300 labels instead of 10,000.

A number I reported was wrong, and here is what replaced it: the SUD proxy label matched "meth" as a substring, so methylphenidate, sulfamethoxazole and dextromethorphan all counted as substance-use related. 803 of 3,316 flagged reviews, 24%, qualified only because of that. A human labelling pilot surfaced it by disagreeing with the proxy more than anyone expected, and someone read the disagreements. Corrected, the trend is 2.0% to 24.8% over 2,513 reviews, not 1.7% to 30.5% over 3,316. I had quoted the old pair.

Caveats: the 37 cohorts predate the label fix and were not re-run. Prior-auth policies and patients are synthetic. The 4th place is self-reported.

Kinematics-Conditioned Surgical Video

Stable Diffusion 1.5 · Diffusers · LoRA (peft) · JIGSAWS · OpenCV

Stable Diffusion 1.5's CLIP text encoder replaced with a custom KinematicEncoder that maps 76-dimensional robot kinematics into cross-attention, fine-tuned with LoRA rank 4 on the JIGSAWS suturing dataset.

The question that makes it interesting: is the model tracking its conditioning signal, or just reproducing the scene average? The evaluation scores each generated frame against its true frame and against a different real frame. If both score alike, the conditioning is doing nothing. That cross-pair baseline is the part I'd defend, though it was only run over four pairs, which is too few to claim much.

Why there are no numbers here: the PSNR and SSIM figures for this model live in a team report rather than in anything committed to the repository, so I don't state them as results. The evaluation code that produces them is in the repo and is linked below.

Method

How I work

Compare against a baseline

A number means nothing without something to beat. ClinIQ ran rules before it ran an LLM; SS-SD scores generated frames against the wrong real frame to see whether the conditioning matters at all.

Make the check structural

If an evaluation can be invalidated by a careless import, a policy in a README will not hold it. The estimator in Silent Failure Detection is blocked from reaching its own labels at the import graph, and the boundary is a test.

Ask what the processing removed

One bug appeared three times in one codebase: a safety check computed downstream of a transform that strips the evidence it looks for. Clipping the outliers before measuring outliers makes the guardrail decorative.

Report the negative result

The lead-time number I set out to produce was zero, and that is what the repository says. A finding that does not survive its own significance test gets retracted in a commit, not quietly reworded.
